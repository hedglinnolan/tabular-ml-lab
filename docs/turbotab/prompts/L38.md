# Part B — the resampling engine, and the plots that are its output

**`research/CLINICAL_SURVEY_PACK.md` §A4.8 — read it first, it is 18 lines and it specifies this
part almost completely.** This is the loop's reason for existing and it is not a figure job.

> *Refit the **entire** modeling pipeline (including any variable selection) in B bootstrap
> resamples, apply each bootstrap model to the original data, and produce: prediction instability
> plot, MAPE, calibration instability plot, classification and decision-curve instability plots.*
> (Riley & Collins, *Biometrical Journal* 2023.)

**Why this is first.** `turbotab/pipeline_plan.py` exists as of L35, so "refit the entire pipeline"
is expressible for the first time. And three open findings collapse into this one build:

- **`GUIDED-103`** — its own note says the selector is *"fold-local BY CONSTRUCTION under any
  resampling."* A resampling loop closes it outright.
- **`GUIDED-104`** — once resampling exists, `scope=train_folds` becomes *true*, so recording it is
  correct rather than an overclaim. The divergence note disappears because the divergence does.
- **`GUIDED-102`** (L37) — `PRODUCT_VISION.md`:296 says that at small n *"the prediction-instability
  plot and the resolution statement stop being supplementary and become the headline."* L37 ships
  the resolution statement. **Without this part that promise is half-delivered**, and the app tells
  a user their holdout resolves nothing while offering no alternative.

**Build the engine, then the plots.**

1. **`B` is a stated number with a stated reason.** Riley & Collins recommend on the order of 1000.
   Pick what this app can actually run, put it in one named constant, and **say the number in the
   figure's own caption** — the posture `recipes.SCALE_THRESHOLD` already takes. A resample count
   nobody can see is a threshold nobody can disagree with. Do not silently use 20 because it is
   fast; if the honest number is 200, the caption says 200.
2. **The whole pipeline, including selection.** A bootstrap that refits the estimator over a fixed
   feature set measures the wrong thing, and `A4.8` says *including any variable selection* in
   italics for that reason.
3. **The prediction instability plot** — bootstrap predictions vs original-model predictions, one
   point per patient per bootstrap — plus **MAPE**, and the **calibration instability plot** (all
   bootstrap calibration curves overlaid). Those three are the deliverable.
4. **Classification and decision-curve instability plots are deliberately deferred** to Part D,
   because the decision curve does not exist yet.

**Then close what it unblocks:** record `scope=train_folds` where it is now true (`GUIDED-104`),
and take `GUIDED-103` to `FIXED` with a probe that a selected set moves across resamples on a
table where it should and not on one where it should not.

**And the bootstrap runs as a job.** `PRODUCT_VISION.md` §04: anything over ~1s is an observable
job with a name in plain language, progress and a cancel. B resamples of a full pipeline is the
longest thing this app will ever do.

# Part C — the manuscript, validated and exportable

**`GUIDED-107`. The product owner has ruled on both open questions — the rulings are in
`PRODUCT_VISION.md`, in the subsection above the resolution statement. Read them; do not re-derive.**

Four things, and the first is the one with a correctness consequence.

**1 · Wire the validator that already exists.** `ml/manuscript_validator.py::validate_manuscript_bundle`
extracts the analysis n, the final predictor count and Table 1's overall n from rendered text and
**checks them against each other**; checks the model named in the prose is the model selected; and
flags metric terms invalid for the task type. It is reachable only from `pages/10`.
`turbotab/draft.py` imports nothing from `ml/`. **`AUDIT-001` was exactly this class** — a section
composed correctly in isolation, asserting what no other section supported — and Report shipped at
L36 without the machine built to catch it. Reuse it; do not write a second one.

**2 · The manuscript becomes data.** `draft.py` composes one **structured document**; two thin
renderers emit Markdown and LaTeX, the latter through `ml/latex_report.py` — 1,066 lines, already
detainted, imports headless, and the exporter Classic uses. *"One core, no forks"* means neither
door holds a private exporter. The ruling records why the larger scope was chosen: **L10's
checklist engine has to read the manuscript**, and a checklist cannot be run against prose.

**3 · Figure promotion, per the ruling: promoted as the author marked it.** `promotable` and
`promotable_because` have sat on every figure spec since L26 with no consumer — `ROADMAP.md` names
it one of three front-half designs that are unfalsifiable until something downstream consumes them.
Report is that consumer. **No tier annotation is added to the caption.** The manuscript is the
author's document.

**4 · But do not launder the record.** The tier stays on the figure, and the **validator** is where
a promoted `EXPLORATORY` figure is reported — a cross-section check in the validation report, not a
caveat in the prose. The author gets the document they asked for and a separate honest list of what
a reviewer will notice.

# Part D — the clinical figures, hardest-first

Four figures from `research/CLINICAL_SURVEY_PACK.md`. **Ordered hardest-first on purpose**, per
`LOOP.md` §02: five instances built easiest-first are five castings of a shape nobody stress-tested.
The figure spec machinery has carried six figures and has stopped bending, so this is fill-out —
**except for the first one, which may not be.**

**D1 · Kaplan–Meier (§A4.6). Expect this one to refuse, and let it.** It needs a **time + event-
indicator pair**, and this app's `task_type` knows only classification and regression. There is no
time-to-event target, no censoring concept, and no way to declare one. **Do not invent a survival
target type to make the figure drawable.** If the honest outcome is that KM cannot be drawn because
the app cannot represent what it needs, that is the result — file it, state precisely what is
missing, and move to D2. A figure that draws from a target the app cannot verify is worse than one
that does not draw.

And note §A4.6's own `SETTLED` warning before writing any of it: **under competing risks,
1 − KM overestimates cumulative incidence**, because KM treats the competing event as censoring.
The pack names it *a very common error*. So even with a survival target, the naive figure is a
named anti-pattern, and the correct behavior is to detect competing risks (event indicator with >2
levels, or a death/other-cause column) and report the **Aalen–Johansen cumulative incidence
function** instead — or refuse and say why.

**D2 · Decision curve analysis (§A4.5)** — the clinical-utility figure, marked ★. Needs predicted
risks and a threshold sweep, both of which exist after Part B.

**D3 · Forest plot (§A4.7)** — **log-scale x-axis for ratio measures is marked non-negotiable**, and
it is labeled *"model coefficients,"* not *"risk factors."* Both are in the spec; honor both.

**D4 · ROC curve (§A4.4)** — the easiest, and last for that reason. Note the pack ranks calibration
above discrimination (§A5.1, §A5.3), so this figure's companions and caption must not present it as
the headline.

**Then the instability plots Part B deferred**: classification and decision-curve instability, now
that the decision curve exists.

# Part F — the probe

**Choose it from what Parts B–E actually surfaced**, and say why you chose it. Two candidates, and
the first is stronger if Part B landed:

- **The resampling probe.** Part B makes every fitted statistic reproducible under a different
  sample for the first time. `test_the_seal_holds.py` asserts no held-out row moves a fitted

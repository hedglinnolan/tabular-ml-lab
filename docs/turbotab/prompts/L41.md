# Part B — the clinical import detectors · **WIDE, hardest-first**

**The clinical pack holds one prior and zero detectors against a 1,209-line research file.**
`packs.py` — `detectors=()`, with a comment arguing the thinness is the point because physiologic
bounds live in the core. That argument was true when written and is not true of §A1.3, which
describes machinery nothing in this repository has.

**Source of truth: `research/CLINICAL_SURVEY_PACK.md` §A1.3 — read that section first**, plus
`DOMAIN_SCIENCE.md` §03b's clinical rows. Follow `nutrition.py`'s detector shape.

**Build as many as you can hold, ordered hardest-first.** Judge "hardest" by what is most likely to
bend the detector contract, not by effort. My ordering, and say so if you disagree after reading:

1. **Censored lab values (§A1.3).** The hardest and the one most likely to bend the contract,
   because it produces a **per-analyte table** rather than one finding — left-censoring fraction,
   the detection limit inferred as the modal `<X`, % above ULOQ. Detect the tokens §A1.3 lists:
   `<`, `>`, `≤`, `≥`, `<LOD`, `<LLOQ`, `>ULOQ`, `TNTC`, `undetectable`, `not detected`, `trace`,
   `QNS`, `hemolyzed`, `see comment`, `pending`, `cancelled`.

   **Carry the three positions §A1.3 states and do not collapse them.** The 10% warning threshold is
   **CONVENTION**, not a proven cutoff. The substitution question is **DISPUTED** below ~5–10%
   censoring and indefensible above ~20%. And the **prediction/inference asymmetry is CONVENTION** —
   *below detection* is real, reproducible clinical information available at deployment, so a
   censoring indicator plus a substituted value is often defensible for prediction and never for an
   unbiased exposure–outcome estimate. **`purpose` is already recorded and this is a second consumer
   for it.**

   **And `TNTC` and `QNS` are not censoring** — they are measurement failures and route to missing.

2. **Text columns >80% numeric-parseable**, and **result columns mixing quantitative with
   qualitative** (a troponin column holding both `0.04` and `negative`). Same section, cheaper, and
   the second is the one a generic profiler reads as a categorical.

3. **Bimodal analyte at a known conversion ratio** (§03b) — glucose ×18.0, creatinine ×88.4,
   cholesterol ×38.67, height in/cm, temperature °F/°C. **This is a hard stop.**
   `DOMAIN_SCIENCE.md` §01.2 is explicit that conversion depends on molecular weight for many
   analytes and that official LOINC/UCUM services themselves error on it. **Detect, declare, never
   convert, no pre-selection.**

4. **Repeated-digit / default-value mass** at 120/80, 98.6, 0 (§03b) — a documented EHR artifact of
   value preference and manual entry, not measurement.

5. **Temporal implausibility** (§03b) — adult height moving >5 cm between visits, weight ±30% in
   <30 days, labs timestamped after death. Needs the repeated-measures chain, which exists.

6. Thousands separators, European decimal commas, scientific notation (§A1.3).

**The coaching sentence this pack exists for goes in with them**, from §03b, because it is a
correction to behavior the app ships: *four systolic values below 30 mmHg are physiologically
impossible in a living outpatient and almost certainly entry errors; the 812 values above 140 mmHg
are abnormal but real and must be kept, because excluding them removes the sickest patients.*
**Physiologically impossible and statistically extreme are different categories, and no generic
outlier rule (±3 SD, IQR fences) can tell them apart.**

Every detector reaches an upload, and every one carries a badge and a resolving source or the
evidence gate refuses the commit.

# Part C — the survey pair, deliberately a different shape

Part B is column typing and parse detection. **C is block structure and a recorded decision reaching
a consumer** — different enough to show a seam if the detector contract has one.

**C1 · Sentinel codes in a bounded block — §B1.1 calls this "the highest-yield check in this pack."**
Flag values that break the observed contiguous run: `7`, `8`, `9`, `77`, `88`, `99`, `-1`, `-8`,
`-9`, `98`, `999`, SAS special missing, `NA` strings. **In a 1–5 item a `9` is not "extremely
agree," it is "don't know" or "refused."** Infer the response support from the **union across the
block**, never per item — a rarely-endorsed extreme may be absent from one item, and that is
§B1.1's own instruction.

**It is a hard stop and it must say so**: SETTLED that sentinels must be recoded, and **never
auto-recode, because some legitimate scales do run 0–9.** Report the shift the coaching sentence
promises — *a 9 treated as a response would move this item's mean by X* — because that number is
what makes it actionable rather than a warning.

`_ordinal_declared` and `_LIKERT_SETS` already exist in `packs.py` and already find blocks. **Extend
them; do not build a second block detector beside the first.**

**C2 · The reverse-coding audit, §B1.2 — file it as `GUIDED-136`.** The app **already asks**:
`api.py:513` dispatches `set_reverse_coding`, `packs.py` carries the `reverse_coding` prior as the
one deliberate exception to `DOMAIN_PACKS.md`'s guard #1, and the question renders. **Nothing scores
it.** That is trap #1 in `AGENT_ONBOARD.md` §07 — a recorded decision with no consumer.

Build §B1.2's **reverse-coding audit table**: item | text (truncated) | item–rest *r* (raw) |
reversal declared? | item–rest *r* after reversal | status. **Re-rendered after every declared
change**, which is the clause that makes it an audit rather than a report.

The central constraint is SETTLED and is the whole point: **TurboTab will not infer reverse-coding
from correlations.** A negative item–rest correlation has four incompatible explanations — needs
reversing, already reversed upstream, a method factor from mixed wording, or it does not belong to
the scale — and **correlations cannot distinguish them.** After a declared reversal, re-run and warn
if an item is *still* negative: either it was already reversed in the source, or it does not belong.

0.30 is **CONVENTION** (Nunnally & Bernstein), never a law, and never stamped PASS/FAIL.

**Polychoric correlations are `GUIDED-127` and stay unbuilt.** §B5.4 is SETTLED that they are the
right choice and nothing here computes one, so this uses Pearson, **says Pearson**, and carries the
direction of the bias — the same disclosure L40 shipped for the survey figures. Do not approximate
one.

# Part D — the probe: the class that hid a defect for six loops

**`GUIDED-134`.** L40 found that the calibration plot had declared a companion called
`discrimination` since L26 that was never registered — so `figures.bundle` held the figure on every
project for six loops. **The guard that should have caught it is the one that hid it:**

```python
FIG.bundle({"calibration": payload, "discrimination": {}})
```

A bare dict key, never a registered figure. `bundle()` skips unregistered ids (`REGISTRY.get` →
`None` → `continue`, on a line marked `# pragma: no cover` that this very test executed) while
`admissible()` reads only the **key set** — so `n_admitted` came back 1, the rule looked enforced,
and no project could ever produce that key. **The test manufactured the production object whose
absence was the defect.**

**This is not the "a guard testing its own description" class**, which this project has hit seven
times and where the test asserts a sentence about the code. Here the **assertion is right and the
fixture is wrong**, which is why reading assertions never finds it.

**Sweep the `turbotab/` test tree for the shape**: a test passing a literal id, key, name or route
into something that resolves it against a registry. Figure ids, pack keys, decision kinds, model
keys, route strings, checklist item ids, annotation keys. For each, assert the stand-in resolves in
the real registry — **or record why it legitimately should not**, in the file rather than in a
comment.

**Report the counts**: sites found, stand-ins that resolve, stand-ins that do not, and how many of
the non-resolving ones were load-bearing for the test's claim. **The last column is the finding.**

And say what the same lens would find one surface over. That check is how the L40 adjudication found
`GUIDED-133` — the decision curve's risk rug is capped at the first 200 rows and nothing says so —
one line past the fix L40 had just shipped.

### A1 · `DRIVE-043` — the Methods section calls the minority the event

`turbotab/resolution.py:379` *(re-derived at `ca3fb4e`)*:

```python

events_test = int((in_test == minority).sum())
```

`minority` is the **least frequent level**, never the recorded decision. Line **494** then renders it
as *"with {n} of the held-out rows carrying the outcome"*. On the drive's `meds_hbp` — `True` 87.77%,
and the user chose `True` — **Methods printed 116 while every figure payload printed 829 events on the
same 945 rows.** 945 − 829 = 116 exactly: the non-event count under an events label.

**Read this next part before you touch anything, because it decides the fix.** **The quantity is
deliberate and correct, and the label is not.** `resolution.py:405-408` and `web/index.html:4848-4852`
carry the *same* documented reason for holding arithmetic rather than a class value —
`archive.assert_no_participant_data` rejects a serialized class label — and **the page renders that
identical field honestly** as *"116 of the less common outcome"* *(re-derived at `ca3fb4e`)*.

**One field, two renderers, and only the one that leaves the building is false.**

**Do not change `events_held_out`.** Its comment and the archive guard are both right. Either the
Methods sentence adopts the page's wording, or Methods reads the recorded event and counts *that* —
**say which you chose and why.** The second is a build and is the better answer if it is reachable;
the first is one line and is honest.

**A1b · The guard is the part that must not be skipped.** Two renderers of one field disagreed for as
long as both have existed. **Assert them against each other**, so a future edit to one cannot silently

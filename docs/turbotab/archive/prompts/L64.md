## Part A · `GUIDED-245` — the wrappers answer, and a sentinel is the only shape that works

**First, because it is the highest-value user-visible defect open and its answer is known.**

### A1 · The defect, driven

Fitting **only `glm`** on `clinical_risk.csv` / `readmit_30d` gives `positive_label=None`,
`has_predictions=False`, and **calibration, decision curve and ROC all absent from the served
bundle**. Only-`logreg` draws all three. `rf` behaves the same way. L63 fixed the *ordering* half —
`predictions_for` now takes the first calibratable run — so a user who ticks a good model alongside a
bad one is fine. **A user who ticks one bad model is not.**

**The cost is four things, not three.** Beyond the figures, `manuscript._calibration_text` reads the
per-figure `drawn` flag, so **the LaTeX export silently drops** *"Calibration was assessed
graphically; the calibration plot is reported with its intercept, slope and C-statistic."* Driven:
`glm` → absent, `logreg` → present. **The resolution statement is NOT a casualty** — `resolution.py`
mentions `positive_label` only in a comment and derives `event_is_recorded` from the recorded answer.
Do not claim it is.

### A2 · The fix, and both obvious versions are broken

`models/base.py` already forwards `coef_` and `intercept_` with a read-only property. **That mechanism
transfers, with one amendment, and the two naive versions both break `nn`:**

- **A plain read-only property fails at `NNWeightedHuberWrapper.__init__`** — not its `fit` — with
  *"property 'classes_' … has no setter"*, because `nn_whuber.py` assigns `classes_` before any data
  exists. **The nn wrapper would stop constructing.**
- **"Defer to the instance attribute if it is not `None`" also fails**, because `nn` assigns `None`
  and then reads it back as `is not None`. A `None`-check falls through to `self.model` — a torch
  module with no `classes_` — and raises.

**So the property must use a SENTINEL**, so that an explicitly-assigned `None` is returned as `None`,
plus a setter. **A verifier applied exactly this and drove the result**: glm-only then admits all
three figures, `has_predictions_because` returns to *"There are predictions and the curve should be
drawn"*, an unfitted glm still reports `hasattr` **False**, an RF regressor still reports False, a
`Pipeline` forwards it, and `clone()` of a fitted wrapper correctly has no `classes_`.
`coef_` is read-only because no wrapper assigns it; `classes_` needs the setter because one does.

**The fallback if the base-class change is judged too broad** is to read the wrapped estimator at the
point of fit in `training.py` — smaller blast radius, works for glm/rf, but it leaves the wrappers
still lying about themselves to every other consumer. **Refusing the figures is NOT the answer here**:
the app already has the information, and refusing chooses the false-absence branch when the true one
is available.

### A3 · Exactly one test goes red, and it must not be deleted

`test_a_project_whose_models_all_record_no_event_still_refuses` fails **with its own message**: *"this
fixture's models now record an event, so it no longer exercises the refusal — `GUIDED-245` may be
fixed."* Its purpose — that a project where **nothing** records an event still refuses rather than
guessing `1` — is correct and must survive. **Replace the fixture** (a hand-built result with
probabilities set and `positive_label=None`, or a stub wrapper); it currently relies on `rf` being
broken. **Do not delete the test**, and **do not weaken the refusal in `predictions_for`** — guessing
`1` is right on a 0/1 target and silently wrong on `responder`/`non-responder`, which is `GUIDED-093`.

### A4 · Two defects found by driving this, both worth folding in

- **A glm-only project is told the ROC and the decision curve *"do not apply to this project."***
  `_why_not` special-cases only `calibration`; ROC and DCA hit the generic fallback, which carries a
  `# pragma: no cover` and **is reachable**, and that string reaches the browser. **The
  assert-something-false branch, on the surface whose job is explaining a silence.**
- **`has_predictions_because` contradicts `has_predictions`** whenever one model records an event and
  another does not: ticking `['glm','logreg']` draws all three figures while the served state says
  *"GLM produced probabilities without recording which class they are about… Fit a model that records
  its outcome level."* An L63 leftover — `predictions_for` was fixed, the `unnamed` branch beside it
  was not. **Fixing `classes_` hides both on these fixtures and fixes neither mechanism.**

### A5 · The generalized guard, and what it must not do

`test_a_wrapped_estimator_forwards_its_coefficients.py` exists **because a wrapper dropped an
attribute** and contains **zero** occurrences of `classes_`. **Naming today's three attributes is how
this recurs** — L56 named two and the third stayed missing for seven loops.

**Derive the attribute set from the estimator**: enumerate concrete `BaseModelWrapper` subclasses,
fit each on a task it declares it supports, and for every trailing-underscore public attribute present
on `wrapper.model`, assert `hasattr(wrapper, attr)` — **and assert the negative direction too**, that
`hasattr` is False where the estimator lacks it and where the wrapper is unfitted. Skip `nn` and
**report the skip**.

**Also**: `models/rf.py` defines `predict_proba` and `supports_proba` **twice**, and the second copy
shadows the first. Editing the first has no effect. **Four stale line references** point at
`training.py`'s event-recording site, including one **inside `GUIDED-245`'s own `ev` field** — correct
them while you are there.

## Part D · The instruments — `TEST-107`, `TEST-108`, `GUIDED-247`, `MISC-028`

### D1 · `TEST-107` — drop the pre-filters; do NOT build a ceiling

**Measured: removing both filters gives byte-identical counts and costs +0.65 s** (0.600 → 1.251 s,
median of five) on a 52-module corpus where only 4 and 5 modules carry the literals.

**A ceiling is the wrong instrument here** and the row's `act` is wrong to suggest one. The quantity it
would bound — modules skipped, 48 and 47 of 52 — **grows every time an unrelated module is added**, so
it would go red for reasons unrelated to claims going unchecked. `repo_write_guard`'s ceiling bounds
destinations the instrument **knows** it cannot see, which is a different quantity. *(Its precedent
lives in the test file, not the helper the `act` names.)*

**The half that matters more: make the counts ASSERTABLE.** Factor the walks out of `check()` exactly
the way `call_sites()` already was — its own docstring says *"A gate whose only interface is stdout is
a gate a test can only check the description of."* Then assert **floors**. **Warn: a zero-guard is
insufficient** — 32 of the 67 claims come from an unfiltered loop, so breaking the filter leaves 32,
not 0. Drive the positive control by pointing the walk at an empty module list and watching it go red.

### D2 · `TEST-108` — extend the search, and add the third state

**`--git-common-dir` is ABSOLUTE inside a linked worktree but RELATIVE in a plain repo**, so the naive
`dirname` of it yields `.` or `..` and works today only because both hooks `cd` to the toplevel first.
**Require `--path-format=absolute`, or prefer `git worktree list --porcelain | head -1`**, which named
the main worktree correctly from all four positions with no flags.

**Extend the search, do not replace it** — a worktree with its own venv should still prefer it, and the
environment override must keep winning first.

**And the second half is the one the row is really about.** The hook's *"no Python interpreter found"*
branch is **unreachable**, because the resolver falls back to a bare `python3` and returns success with
a dependency-free interpreter. **That fallback is what manufactures the false red** `lib.sh`'s own
header warns about. **Add a third state so a gate that CANNOT RUN does not print the same ✗ and the
same "COMMIT REFUSED" as a gate that failed.** The proving assertion: run the hook inside a throwaway
`git worktree add` and assert no ✗ attributable to a missing module.

### D3 · `GUIDED-247` — take the add, and insist on the caller's count

# `clinical_labs.csv` — expected findings

**288 rows × 19 columns**, 96 patients × 3 visits. `patient_id`, `visit_date`,
`site`, `age`, `sex`, `height_cm`, `weight_kg`, `sbp`, `dbp`, `temp_f`,
`glucose`, `hs_crp`, `ferritin`, `wbc`, `troponin`, `platelets`, `creatinine`,
`bnp`, `readmitted`.

Generated by `make_fixtures.py::clinical_labs`, seed `770118`.

**Why it exists.** The clinical pack held one prior and zero detectors against a
1,209-line research file, under an argument that the thinness was the point
because physiologic bounds and unit harmonization already live in the core. That
was true of **§A1.2** — the pack reads `ml/physiology_reference.py`'s bands
rather than carrying its own — and it was never true of **§A1.3**, which
specifies censoring tokens, detection limits inferred from the data, and result
columns carrying a qualifier inside the value. None of that existed anywhere.

**One table rather than six**, because §A1.3's own framing is that these arrive
together. A real multi-site extract carries censoring tokens, a column typed as
text because of them, an analyte reported in two units by two sites, and a
vitals column with a manual-entry spike, all at once. Six single-property files
would make each detector easy and the interaction untested.

**It is longitudinal** because temporal plausibility (§A1.2, Kahn et al.) is a
claim about a trajectory and cannot be built on a cross-section.

**The censored fraction is 19% on purpose.** §A1.3 puts the warning threshold at
10% (**CONVENTION**, in its own words) and the substitution dispute between
roughly 5–10% and ~20%. A fixture at 4% would make the DISPUTED clause
unreachable and one at 40% would make it uninteresting; 19% is the only region
where both positions are live.

**The severe-hypertension arm is the coaching sentence's other half.** One
patient in nine runs at hypertensive-urgency pressures. Without them the file
would carry four impossible values and nothing to contrast them against, and
§03b's sentence needs both counts or it is not the sentence.

## Must surface

All eight clinical detectors, reachable from an upload under the clinical lens:

- `pack::clinical::censored_values` — 2 analytes, `hs_crp` at 19.1% below a
  modal limit of 0.3, `ferritin` above ULOQ, and `QNS`/`TNTC` named separately
  as measurement failures.
- `pack::clinical::text_numeric` — `wbc`, `ferritin`, `troponin`, `hs_crp`.
- `pack::clinical::mixed_result_type` — `troponin`.
- `pack::clinical::mixed_units` — **`critical`**, `glucose`, and **nothing is
  converted**.
- `pack::clinical::default_value_mass` — `dbp` at 80, `sbp` at 120, `temp_f` at
  98.6.
- `pack::clinical::temporal_implausibility` — `PT0007`'s height, `PT0021`'s
  weight.
- `pack::clinical::number_format` — `creatinine`, `platelets`.
- `pack::clinical::impossible_vs_extreme` — **`sbp`, and not `glucose`.**

## Must NOT surface

- **`glucose` as 120 entry errors.** The core flags it `whole_column_suspect`,
  because 42% of it falls below the mg/dL floor — that is the *unit* finding,
  at `critical`, and `impossible_vs_extreme` sets the column aside and says so.
  A coaching card telling a user to set 120 correctly-measured values to
  missing is the false authoritative assertion this pack exists to prevent.
- **Any survey, metabolomics, genomics or dietary finding.** The wide block of
  lab columns and the censoring tokens are the two nearest misses in the
  repository, and `test_a_pack_does_not_fire_on_the_wrong_data` runs the whole
  matrix against this table for exactly that reason.
- **A repair offer on any of the eight.** Every one is `fix_kind="none"`.
  §A1.1's design rule is *detect, propose, require explicit confirmation*, and
  `DOMAIN_SCIENCE.md` §01.2's litmus is that the data cannot distinguish the
  causes.

## What this fixture cannot show

- **Scientific notation as a parse failure.** `bnp` is written `6.4E+01` and
  **pandas parses it natively**, so the column arrives as `float64` and the
  format detector never sees it. The pattern is kept because it is reachable on
  a column that is text for another reason; on its own, scientific notation is
  a number here. Stated rather than engineered around: making it fire would
  have meant re-reading the source file from inside a detector whose contract is
  a DataFrame.
- **Labs timestamped after death.** The detector reads a `death`/`dod` column
  and this file has none — the fixture is a live outpatient cohort. The branch
  is covered by a constructed frame in the test file and named there.
- **Pediatric growth.** §A1.2 is explicit that adult height bounds must never be
  applied to a growing child, and the detector excludes rows under 20 and
  reports the count. Every patient here is 31 or older, so the exclusion path is
  exercised by the test file rather than by this fixture.
- **Two detection limits in one analyte.** An assay change mid-study is a real
  finding and `limits_seen` carries it; this file has one limit per analyte.

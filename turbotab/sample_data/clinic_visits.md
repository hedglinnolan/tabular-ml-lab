# `clinic_visits.csv` — the control

**140 rows × 14 columns.** The generic messy fixture, present since the walking
skeleton. It is not generated by `make_fixtures.py` and must not be regenerated:
its value is that it predates every pack and was not shaped by any of them.

Its job in the fixture set is **guard #2** from `DOMAIN_PACKS.md` §03, made
executable:

> **Every pack, installed together, adds zero new questions to this file.**

A pack that fires on non-matching data has failed regardless of how good its
content is. The value check's `irrelevant_questions` metric already measures
this, and this file is the measurement's subject.

---

## What it already produces, with no lens

Ten structural findings, all correct readings of a genuinely messy file:

| Finding | Severity |
|---|---|
| `sentinel_missing__age`, `__glucose` (999, far above every other value) | warning |
| `positive_class__outcome` | warning |
| `category_variants__sex` | warning |
| `numeric_as_text__income`, `__weight` | warning |
| `text_missing__notes` | warning |
| `unnamed_columns` | warning |
| `constant_columns` | info |
| `wide_repeated_measures` (`bp_1`, `bp_2`, `bp_3`) | info |

`bp_2`'s two readings of 99 mmHg are no longer read as a missing-value code (audit IN-04, WP14):
99 is the column's lowest reading, one mmHg below the next, a real extreme rather than a code
beyond the observations. The two 999s are warnings, not critical: nothing but the numbers says
they are codes (no codebook corroborates a clinic export).

Plus one advisory plausibility hit on `glucose`, and a task detection of
classification at high confidence against `outcome`.

---

## The control's assertion

Installing all five packs changes **none** of the above and adds **no** question.

The number that matters is questions added, not findings changed. A pack that
reframes an existing finding without asking anything new has not violated guard
#2 — but on this file no pack should have anything to reframe either, because
nothing here matches any pack's shape:

- no run-order column and no acquisition sequence;
- no macronutrient columns and no composition summing to a constant;
- no Likert block and no declared response scale;
- no count matrix and no p ≫ n;
- `bp_1`/`bp_2`/`bp_3` is a genuine wide repeated-measures family, which is what
  that finding is *for* — unlike `mz_0001` or `gene_0001`, where it is a false
  alarm.

The last point is the one worth reading twice. The same finding is correct here
and wrong on three other fixtures, and the only thing that distinguishes the
cases is the lens. That is the whole argument for asking the question.
